# 数据上下文说明（给 Coding Agent）

本项目的 RAG / 生成流水线主要使用 `data/` 目录下的多个子数据源。下面按子目录，说明典型文件结构与语义，便于 Agent 正确理解和解析。

---

## 1. `data/archdaily/` — 国际建筑案例（ArchDaily 爬取 JSON）

- **文件形式**：每个项目一个 JSON，例如 `562296.json`。
- **用途**：为设计理念、陈列展览区、公共服务区等模块提供国际案例文本。
- **典型字段（键）说明**：
  - `"Project ID"`：字符串，ArchDaily 项目 ID。
  - `"Project Title"`：字符串，项目名称。
  - `"Categories"`：字符串数组，功能类型（如 `"Museum"`）。
  - `"City"` / `"Country"`：城市 / 国家。
  - `"Architects"`：字符串数组，建筑师/事务所名称。
  - `"Area"`：总建筑面积（通常带单位的字符串，如 `"4100 m²"`）。
  - `"Year"`：竣工年份（字符串）。
  - `"Project URL"`：原始 ArchDaily 链接。
  - `"Description"`：**数组**，若干自然段文本，来自 ArchDaily 正文（英文）。
  - 领域切片字段（全部为字符串，可能为空字符串）：
    - `"设计理念"`：与整体概念 / 展示叙事相关的文本片段。
    - `"陈列展览区"`：陈列展览区相关空间与功能描述。
    - `"公共服务区"`：公共服务设施、公共可达空间等描述。
    - `"业务科研用房"`：业务科研空间描述（可能为空）。
    - `"藏品库区"`：藏品库房与库区相关描述（可能为空）。
    - `"综合大厅/中庭"`：大厅、中庭等核心公共空间描述。
    - `"特效影厅"`：特效影院、球幕/巨幕等（若有）。
    - `"科教活动"`：教育活动场景、科普叙事等文本。
    - `"建筑形态特征"`：形态特征与体量构成相关描述。
  - `"images"`：图片元数据数组：
    - `filename`：图片文件名。
    - `tags`：标签数组（功能/构件类型等，如 `"Facade"`）。
    - `caption`：图注文字。

> 解析时：既可以把 ArchDaily 原文 `Description` 作为整体上下文，也可以直接使用中文标签字段（设计理念、陈列展览区等）做分区语义切片。

## 2. `data/china/` — 国内科技馆/博物馆案例（结构化 JSON）

- **文件形式**：每个项目一个 JSON，例如 `山东省科学技术馆.json`。
- **用途**：为设计理念、指标对标、功能构成等提供中文结构化案例数据。
- **常见字段（不同文件可能略有差异）**：
  - `"name"`：中文项目名称。
  - `"english_name"`：英文名称。
  - `"opening_date"`：开馆时间（字符串）。
  - `"total_construction_area_sqm"`：总建筑面积（平方米，字符串或数字）。
  - `"floors_above_ground"` / `"floors_under_ground"`：地上 / 地下层数。
  - `"building_height_meters"`：建筑高度（米）。
  - **理念/形态与功能区字段**（字符串，通常为长段落）：
    - `"concept&appearance"`：整体设计理念与外观形态。
    - `"permanent_exhibitions"`：常设展览/展陈区构成与内容（展览空间模块主要用）。
    - `"central_hall"`：中央大厅/中庭空间描述（综合大厅模块使用）。
    - `"special_effects_theaters"`：特效影院/球幕/IMAX 等空间描述。
    - `"science_popularization_activities"`：科普教育活动、品牌活动、流动科技馆等运营内容。

> 解析时：这些字段基本是一维长文本，已经按功能模块切好，无需再从原文中分类抽取。

## 3. `data/world/` — 其它世界案例（JSON 或文本）

- **文件形式**：多为 JSON 或类 JSON 文本，每个文件对应一个世界范围的案例（科技馆 / 博物馆 / 游客中心等），例如 `California Science Center, Los Angeles.json`。
- **用途**：补充国内以外的参考案例，结构与 `china/` 高度相似，字段命名大多复用同一套 schema，个别字段可能省略或增加说明字段。
- **典型字段说明**（与 `china/` 对齐）：
  - `"name"`：项目名称（英文或中英文混合）。
  - `"opening_date"`：开馆或开放日期（字符串，如 `"1998-02-07"`）。
  - `"total_construction_area"` / `"total_construction_area_sqm"`：总建筑面积，字符串形式，可能包含单位（如 `"54348 sqm"`）。
  - `"floors_above_ground"` / `"floors_under_ground"`：地上 / 地下层数（数值或 null）。
  - `"building_height"` / `"building_height_meters"`：建筑高度（字符串，通常带单位，如 `"61 m"`）。
  - **理念与功能区字段**（与 `china/` 对应）：
    - `"concept&appearance"`：整体设计理念与外观形态（英文长段落）。
    - `"permanent_exhibitions"`：常设展览/展陈区构成与内容（展览教育模块主要用）。
    - `"central_hall"`：中央大厅/中庭空间描述（核心公共空间模块使用）。
    - `"special_effects_theaters"`：特效影院（IMAX / dome / 4D 等）描述。
    - `"science_popularization_activities"`：科普教育项目、夏令营、学校合作课程等运营活动。

> 解析建议：
> - 以 `china/` 的 schema 为主，解析 `world/` 时优先尝试同名键（`concept&appearance`, `permanent_exhibitions`, `central_hall` 等），缺失时可回退到更通用的说明字段。
> - 对面积、高度等带单位的字段，可在 ETL 层做数值归一化（提取数字部分并换算为平方米或米），便于指标分析模块使用。

## 4. `data/gb/` — 规范与标准（多来源文本）

- **文件形式**：当前主要为 Markdown 规范全文与条文说明，每个文件对应一部国家标准或行业标准：
  - `博物馆建筑设计规范.md`（JGJ 66-2015）
  - `博物馆建筑设计规范 条文说明.md`
  - `科学技术馆建设标准.md`（建标 101-2007）
  - `科学技术馆建设标准 条文说明.md`
  - `建筑设计防火规范.md`
  - `民用建筑设计统一标准.md`
  - `无障碍设计规范.md`
  - `绿色建筑评价标准.md`

- **用途**：RAG 检索的规范条文来源，用于回答规范类问答与生成设计指标、空间构成原则等提示词。

- **各文件一级目录（示例）**：
  - `博物馆建筑设计规范.md`：
    - `# 《博物馆建筑设计规范》 JGJ 66-2015`
    - `## 1 总 则`
    - `## 2 术语`
    - `## 3 基地与总平面设计`
    - `## 4 功能构成与面积标准`
    - `## 5 建筑设计`
    - `## 6 建筑设备`
    - `## 7 运营与管理`（后续章节标题可能略有差异，但均以数字编号的“总则/术语/基地/功能/建筑/设备”等为一级目录）

  - `科学技术馆建设标准.md`：
    - `# 《科学技术馆建设标准》(建标 101-2007)`
    - `## 第一章 总 则`
    - `## 第二章 建设项目构成`
    - `## 第三章 建设规模和建筑面积指标`
    - `## 第四章 建设标准和功能用房指标`
    - `## 第五章 展教装备配置指标`
    - `## 第六章 投资估算指标`
    - `## 第七章 运行管理与绩效评价`（章标题以“第一章/第二章…”为一级目录）

  - 其它规范文件（如 `建筑设计防火规范.md`、`民用建筑设计统一标准.md`、`无障碍设计规范.md`、`绿色建筑评价标准.md`）通常遵循类似结构：
    - 顶部：`# 标准名称 编号`
    - 章级：`## 总则` / `## 术语` / `## 基本规定` / `## 建筑防火` / `## 无障碍环境设施` / `## 评价指标体系` 等按章编号的一级目录。

- **通用语义层级**：
  - 文件级：某一部规范或标准整体。
  - 章级（`##`）：总则、术语、基地与总平面、功能构成、建筑设计、设备、投资指标等。
  - 条款级（`###` 或 `####` + 条号）：具体的强制性或推荐性条文。

- **Agent 解析建议**：
  - 将每条条文（条号 + 正文）视作一个最小的 RAG 单元，在 metadata 中记录：`standard_name`、`chapter`、`clause_id` 等。
  - 回答规范类问题时，可优先按 `chapter` 过滤（如“基地与总平面设计”、“建设规模和建筑面积指标”等），再在条款内做语义匹配。

## 5. `data/zlj/` — 行业知识库（Markdown 规范手册）

以 `bwg.md`（博物馆） 为代表，是系统中非常核心的领域知识文本。

### 5.1 文件整体结构层级

以 `bwg.md` 为例：

- `# 博物馆`（一级标题）
  - 表示本文件的顶层主题：博物馆建筑（含科技馆等）整体规范与设计要点。

- `## 基本概念`（二级）
  - 定义、规模、类型等宏观概念；
  - 包含若干 `###` 三级标题：
    - `### 定义`：博物馆的功能与属性定义。
    - `### 规模`：
      - 下面的 `####` 四级标题 + 表格：
        - 描述建筑规模分类（特大型馆 / 大型馆 / 中型馆等）及对应建筑面积区间。
    - `### 类型`：
      - 下面的 `####` 四级标题 + 表格：
        - 列出博物馆类型（综合类 / 专题类 / 艺术类 / 自然类 / 科技类）及各自的藏品性质和实例。

- `## 选址及用地`（二级）
  - 描述选址条件、用地规模及与城市规划的关系；可能包含经济技术指标统计表（建筑面积、容积率、绿化率等）。

- `## 总体布局`（二级）
  - 关于人流 / 车流 / 物流组织、室内外展场布局、扩展性等整体布局原则。
  - 包含文字条目与指标表格（如建筑密度、绿化率等）。

- `## 功能构成`（二级）
  - 说明博物馆的核心功能（收藏、展示、教育、公共服务等）。
  - 下挂 `####` 表格，描述“公众区域 / 业务区域 / 行政区域”各自的功能区与主要用房构成：
    - 公众区域：陈列展览区、教育区、服务设施等。
    - 业务区域：藏品库区、藏品技术区、业务研究用房等。
    - 行政区域：行政管理区、附属用房等。

- `## 布局与要求`（二级）
  - `### 流线组织`：
    - 详细描述公众流线、业务流线、行政流线的关系及示意图。
  - `### 陈列与展示`：
    - 展厅类型（常设、临时、室外），空间组合与流线要求。
  - `### 设施与设备`：
    - 展陈设施、照明、贮藏设施、安防设施等设计要求。
  - `### 环境与景观`：
    - 室外展场、景观与主题呼应等要求。
  - `### 展陈设计要求`：
    - 功能配比、流线、空间、采光、荷载等与建筑设计耦合的展陈要求。

- `## 基本构成`（二级）
  - `### 建筑功能区域的构成`：
    - 通过表格给出“公众区域 / 业务区域 / 行政区域”的构成及典型用房类型。

- `## 陈列展览区`（二级）
  - `### 陈列展览区功能组成`：
    - 说明陈列展览区由哪些子空间构成（序厅、常设展厅、临时展厅、儿童展厅等）。
  - `### 设计要点`：
    - 平面组合、观众流线、休息区设置、安全与防护等。
  - `#### 陈列展览区平面组合类型示意图`：
    - 表格与示意图，说明大厅式 / 串联式 / 放射式 / 混合式等组合方式。
  - `### 一般展厅布置形式` & `### 特殊展厅布置`：
    - 展厅布置类型（口袋式、穿过式、混合式等）及适用场景、示意图。

> 总体上，Markdown 的层级语义可以理解为：
> - `#`：建筑类型 / 大类（如“博物馆”）。
> - `##`：该类型建筑的一级专题（总体概念、选址、布局、功能构成等）。
> - `###`：每个专题下的子话题（如流线组织、陈列与展示等）。
> - `####`：更细的子条目或表格标题，多为指标细节或示意分类。

在向量化时，通常会按段落或小节拆分为多个 `Document`，并在 metadata 中记录：
- `building_type = "博物馆"`
- `section = "功能构成"` / `"陈列展览区"` 等
- `subsection = "陈列展览区功能组成"` 等

### 5.2 `kjg.md`（科学技术馆）结构层级与语义

`kjg.md` 是“科学技术馆”（科技馆）专题知识文件，其层级与 `bwg.md` 基本一致，但内容更聚焦于科技馆这一子类型：

- `# 科学技术馆`（一级标题）
  - 顶层主题：面向科技馆建筑的功能定位与设计原则。

- `## 基本内容`（二级）
  - 说明科技馆的定义与整体职能。
  - `### 定义`：
    - 给出科技馆的机构属性、服务对象（以提高公民科学素质为目的的公益性机构）。
  - `### 概述`：
    - 概述科普教育的三大组成：展览教育、实验教育、培训教育。
    - 下挂若干 `####` 四级小节：
      - `#### 科技馆展示理念`：表格形式，按“职能 / 展品 / 展览方式 / 活动方式 / 观众特点 / 库区”等条目，说明科技馆与传统博物馆在职能和展陈方式上的区别。
      - `#### 科技馆建筑规模分级参考值`：表格给出特大型馆 / 大型馆 / 中型馆 / 小型馆的建筑面积区间与设计使用年限。
      - `#### 科技馆主要构成模式`：表格给出“大型科学城 / 综合科技馆 / 专业科技馆”的内容、主要功能、选址与规模特征。

- `### 科技馆总平面设计`（仍在“基本内容”下的三级标题）
  - 描述不同总平面布局模式：
    - `#### 科技馆总平面布局特点`：表格列出“集中式 / 复合式 / 分散式”三种类型的布局特点（形象突出、流线长度、功能分区独立性等）。

- `## 功能构成`（二级）
  - 聚焦于科技馆的功能用房构成与比例：
  - `#### 科技馆主要功能用房组成及比例参考值`：
    - 表格按“展览教育用房 / 公共服务用房 / 业务研究用房 / 管理保障用房”分类，给出特大型馆 / 大型馆 / 小型馆的面积比例区间。
    - 下方配有示意图，展示平面功能组成与人员流线。

- `## 特效电影院设计`（二级）
  - 针对科技馆内的特效影院空间进行专门说明：
  - 内容要点：
    - 解释“特效电影/特种电影”的定义（环幕、巨幕、球幕、动感、立体电影等）。
    - 概述特效电影院的组成：观众厅、公共区域、影院设备用房。
    - 总体布局要点：影院宜相对独立、设置独立出入口和垂直交通，组织好进出场流线，避免交叉与逆流，并满足疏散与安全要求。

- `## 展览内容`（二级）
  - 引用联合国教科文组织标准，列出科技馆建议涵盖的基础学科（数学、天文、动力、电技术、运输等）和与我国科技/经济发展密切相关的领域（生命科学、环境科学、信息科学、能源、交通、材料、制造、航天、激光等）。
  - 对“展品”的定义：展示的实物、模型、演示装置等。

> 建议在向量化 `kjg.md` 时，metadata 至少包含：
> - `building_type = "科学技术馆"`
> - `section`：如 `"基本内容"` / `"功能构成"` / `"特效电影院设计"` / `"展览内容"`；
> - `subsection`：如 `"科技馆展示理念"` / `"科技馆主要功能用房组成及比例参考值"` 等。
>
> 这样，在设计科技馆项目时，可以：
> - 以 `section = "功能构成"` 检索功能用房比例建议，用于指标与面积配比分析；
> - 以 `section = "特效电影院设计"` 检索特效影院的布局与疏散要求，对接特效影院模块；
> - 以 `section = "展览内容"` 检索展陈主题构成，为“科教活动/展览内容策划”部分提供知识支撑。

## 6. 小结：各数据源在系统中的角色

- `archdaily/`：国际案例 —— 主要提供**具体项目的设计语言与空间组织实例**，已按功能区做了中文切片键（设计理念、陈列展览区等）。
- `china/`：国内案例 —— 结构化文本，按照**项目整体参数 + 各功能板块长文描述**组织，直接服务于对标与生成模块。
- `world/`：全球其它案例 —— 结构可能不完全统一，但语义上等同于 `china/` 与 `archdaily` 的补充源。
- `gb/`：规范与标准 —— 以**条文/表格**形式给出约束条件与指标，是 RAG 回答规范问题与生成“技术指标/设计要求”部分的依据。
- `zlj/`：知识手册（Markdown） —— 面向**建筑类型/专题**的系统性知识，层级清晰，适合按章节检索，支撑“设计理念解释 + 规范化空间构成”的生成任务。

本文件旨在让 coding agent 在读取/修改代码时，能够快速对齐这些数据源的结构与语义，从而更安全地编写 ETL、索引构建和 Prompt 组装逻辑。
